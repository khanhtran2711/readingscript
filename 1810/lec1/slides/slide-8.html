Slide 8

Software for clickstream collection

Teaching cue: 51 to 56. Allow one minute for students to propose a tool-selection criterion. Describe the tools by their role. Avoid turning this introduction into an installation comparison.

The slide names Google Analytics, Adobe Analytics, Snowplow, and Divolte, and it includes the category “open-source software.” These entries do not all represent the same kind of product. Some provide a broad reporting environment. Others focus more on collecting events and moving them into a data pipeline.

Google Analytics 4 gives us an accessible example of event collection linked to reports and explorations. We will use it to practise measurement concepts and validation. Its usefulness still depends on what we configure and what its measurement definitions mean. [4, 14]

Adobe Analytics supports several collection approaches, including web SDK implementations and server-side methods. A team already using Adobe’s environment might evaluate how those options fit its existing systems and reporting needs. Learning the definition of an event remains useful even when the implementation differs. [15]

Snowplow illustrates an approach centred on event data moving through a pipeline. Its documentation describes collection, validation against schemas, enrichment, and delivery to destinations such as a warehouse. A schema specifies the structure and permitted values of a record. This can help a team detect an event that does not match its agreed definition. [16]

For example, suppose our product identifier should be a string but one application version sends a list. A schema validation process can identify the mismatch. That is a data-quality issue with consequences for later joins and reports.

Divolte is a collector example in the deck. Its project describes collecting clickstream data for systems such as Kafka and Hadoop. Knowing that role is sufficient today. Selecting a collector for a new project would require checking its current releases, dependencies, and support. Do not infer readiness simply because its name appears on a teaching slide. [18]

Matomo, mentioned in the deck’s notes, is another analytics platform with an open-source offering. Hosting choices and control over data can be relevant to an organisation’s requirements. Open-source software still requires decisions about operation, updates, and responsibility. [17]

If you were choosing a tool for UniCart, what would you ask first? Take a minute to propose one criterion and explain why it matters.

Teaching cue: Accept questions about required events, integrations, access to event-level data, available skills, operating costs, data control, and how collection can be tested. Ask for the reason behind the criterion.

An analyst should be able to explain a selection in terms of the project. For this class, GA4 provides a common setting in which to learn. Later, you should be able to transfer the same questions about meaning, coverage, and quality to a different platform.
